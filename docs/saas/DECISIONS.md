# החלטות יסוד ל-SaaS (שלב 0)

תאריך: 6.11.2026. התכנית אושרה על ידי Pit, וההחלטות נקבעו לפי התשובות שלו מ-6.11.2026.
התכנית המלאה: https://claude.ai/artifact/KSfHK7LuPWyAGPMxMsb7Fm

הכלל של Pit: לא עוברים לשלב הבא לפני שתנאי הסיום של השלב הנוכחי מתקיים והוא מאשר.

המטרה: בעלים של בית ספר (שחייה או צלילה חופשית) נרשם, משלם, וקבל את כל המערכת ריקה ומוכנה, עם וואטסאפ, סליקה,
קבלות ומוח חכם משלו, ויכול להעביר אליה נתונים מהמערכת הקודמת. רעות (R-SWIM) היא רק לקוחה לדוגמה.

## Morning: מה אומת בתיעוד הרשמי (6.11.2026)

מקור: https://developers.morning.co/api (המפרט עצמו ב-`/docs/openapi.bundled.json`).

- **כתובות:** ייצור `https://api.greeninvoice.co.il/api/v1`, בדיקות `https://sandbox.d.greeninvoice.co.il/api/v1`.
  התחברות: מפתח API מוחלף בטוקן גישה לשעה (`POST /idp/v1/oauth/token`).
- **דף תשלום:** `POST /payments/form` מחזיר קישור לטופס, להטמעה (iframe) או להפניה. השדות: `description, type, amount,
  currency, vatType, lang, maxPayments, pluginId, group, client, income, remarks, successUrl, failureUrl, notifyUrl, custom`.
  אמצעי תשלום (`group`): כרטיס 100, PayPal 110, Bit 120, Google Pay 150, Apple Pay 160. כשהלקוח משלם, המסמך (למשל 320
  חשבונית מס/קבלה) **נוצר לבד**, ו-`notifyUrl` מקבל הודעה.
- **כרטיסים שמורים:** `POST /payments/tokens/search` (חיפוש טוקנים של העסק) ו-`POST /payments/tokens/{id}/charge`
  (חיוב טוקן שמור, ונוצר מסמך כשהחיוב מצליח). זה מספיק לחיוב חודשי: ה-worker מחייב את הטוקן פעם בחודש.
- **Webhooks:** מוגדרים בממשק של Morning (Developer Tools → Webhooks), עם סוד לחתימה וכותרת `x-webhook-topic`.
- **חסר בתיעוד:** אין דרך מתועדת **ליצור** טוקן (לשמור כרטיס), ובמיוחד בלי לחייב, כמו שצריך ב-14 ימי התנסות. נשאל את
  Morning: (1) איך שומרים כרטיס כטוקן דרך ה-API, (2) האם אפשר לשמור בלי חיוב או באימות בלבד (J5), (3) האם המסוף של
  Pit מאשר חיובים חוזרים מטוקן. חלופה אם אין: בהרשמה מחייבים 1 ₪ לאימות ושומרים את הכרטיס, ומחזירים או מקזזים בחיוב
  הראשון.

## מה נמצא תוך כדי (נכנס לשלבים)

- התוכניות (plans) קיימות היום רק בנתוני הדמו (`packages/seed/src/saas-data.ts`), לא במיגרציה. במסד ייצור ריק לא יהיו
  תוכניות, וההרשמה תיכשל. נכנס לשלב 1: נתוני פתיחה לייצור (תוכניות ותבניות) בלי שום נתון דמו.
- המגבלה "תלמידים" נספרת לפי תלמידי שחייה. לצלילה צריך לספור צוללים. נכנס לשלב 4.
- התבנית "תקנון R-SWIM" היא התקנון של רעות. בשלב 4 היא מוחלפת בתקנון כללי לכל בית ספר.
